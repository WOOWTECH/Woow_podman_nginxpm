本目錄為**歷史參考資料**，不是本倉庫的部署路徑，請勿執行；實際部署請用 `scripts/install.sh`。

## Where it came from / 來源

Host `woowtechopenclaw`, directory `~/Woow_podman_nginxpm`.

That directory was assumed to be a clone of this repository. It is not: it has **no `.git` at
all** — no remote, no history, no bundle — and the SHA recorded in its `.deployed-commit`

`nginx-proxy-manager-healthcheck.timer` ran `tree/scripts/healthcheck.sh` on a timer.

## What it deployed / 部署內容

`nginx-proxy-manager` (`jc21/nginx-proxy-manager:2.15.1`, digest-pinned) as a single
`podman-compose` project named `nginxpm`: container `npm-app` on the `npm-network`,
`odoo18-network` and `pi-agent` networks, publishing `0.0.0.0:80`, `0.0.0.0:443` and
`127.0.0.1:18081 -> 81` (admin on loopback only). A hand-written `nginx-proxy-manager.service`
(oneshot, `UMask=0077`, `TimeoutStartSec=900`) drove `deploy.sh`, with a healthcheck
service + timer pair alongside it.

The layer around the compose file is the part worth keeping: an owner-id / lifecycle-lock model
(`tree/scripts/lib/common.sh`, 22 KB) that made deploy, backup, restore and remove refuse to touch
resources a different owner had created; a backup format with a manifest, a sha256 and an archive
validator (`tree/scripts/lib/validate_backup.py`); an NPM API client used to assert the admin
account really exists and the database is not empty (`tree/scripts/lib/npm_api.py`,
`check_empty_db.py`); and a bash test suite of roughly 1 800 lines.

## What looks reusable / 可再利用之處

`tree/tests/fixtures/` is the reason this is worth preserving. It is **hand-captured real podman
4.9.3 output**, not invented shapes:

* `tree/tests/fixtures/verify/*-port-bindings.json` — real `.HostConfig.PortBindings` JSON,
  including the two shapes that have repeatedly caused bugs in this project: the JSON key is
  `HostIp` while the Go struct field is `HostIP`, and a catch-all binding is `"HostIp": ""`, an
  **empty string** — not `0.0.0.0`, and not an absent key. `podman-4.9-port-bindings.json` is the
  4.9.3 shape; `standard-port-bindings.json` is the `0.0.0.0` shape newer podman prints.
* `tree/tests/fixtures/verify/*.ss` — real `ss -ltn` listener output: `*:80`, `[::]:443`, the
  IPv6-only case, and the unsafe variants where the admin port escapes loopback.
* `tree/tests/fixtures/podman` — a fake-podman shim that replays true 4.9.3 responses
  (`podman version` → `4.9.3`; a missing object → `Error: no such container` on stderr and exit
  125) from a state file. `lifecycle_podman` and `lifecycle_compose` are larger versions of it.
* `tree/tests/fixtures/npm_api_server.py`, `lifecycle_api.py` — a stub NPM API, used to assert the
  admin account exists and the restored database is not empty.

**Assessment against the current tests.** The current repository already solves the
`.HostIp` / `.HostIP` problem, and solves it better: `tests/gotmpl.py` resolves Go field names the
way podman's template engine does, and `tests/inspect-templates.sh` asserts that `{{.HostIp}}`
*fails* the way podman fails it rather than silently rendering empty. These fixtures do not improve
on that. What they would add is the **listener half**, which the current tests do not cover
offline: the `.ss` fixtures plus `tree/tests/unit/verify_ports_test.sh` could become a port-safety
test beside `tests/inspect-templates.sh`, asserting that the admin port stays on loopback across
the `*:`, `[::]:` and IPv6-only shapes, and that no extra public listener appears.
**Deliberately not done in this change** — preservation first; rewiring the live tests is separate
work that deserves its own review.

## What was excluded / 已排除的內容

No preserved file was modified; files that could not be preserved were dropped whole rather than
edited, so nothing under `tree/` is a partial or doctored version of a host file.

**Excluded for secrets (2 files)**

* `.secrets/npm-admin.env` — the live Nginx Proxy Manager admin password in plain text. The file
  held exactly two keys, `NPM_ADMIN_EMAIL` and `PASSWORD`. **Treat that password as disclosed and
  rotate it.**
* `.env` — the host copy. It differs from the preserved `tree/.env.example` in one line
  (`NPM_ADMIN_EMAIL`), carries no secret, and is ignored by this repository's `.gitignore`.

**Excluded as worthless (18 files)**

* `backups/npm-backup-*.tar.gz` with their `.manifest` and `.sha256` (15 files) — runtime archives
  of live NPM state. They contain the NPM database (password hashes) and Let's Encrypt material,
  and the archive format is fully described by the preserved `backup.sh`, `restore.sh` and
  `validate_backup.py`.
* `.state/checkout`, `.state/owner-id`, `.state/lifecycle.lock` — host runtime state: a checkout
  path, that host's owner hash, and an empty lock file.

**Excluded as already present (0 files)** — no file in this tree was byte-identical to a file
already in this repository.

A value-shaped secret scan over `tree/` (GitHub PATs, `sk-` keys, Slack tokens, AWS key ids, PEM
private keys and certificates, JWTs, tailscale/headscale auth keys, bcrypt and crypt hashes, and
non-placeholder `*PASSWORD|SECRET|TOKEN|_KEY=` assignments) reports **0 hits**.
